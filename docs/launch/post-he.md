# whipple3 — לוח משותף, מוקלד ומבוסס-אירועים, לתיאום בין סוכני AI

> **טיוטה — לא לפרסם לפני שה־checklist ירוק.** מקומות שמורים: `[הקלטת סטודיו]`,
> מספרי הבנצ'מרק. יעדים: קבוצות dev ישראליות, טוויטר/X בעברית, מיטאפים.

סוכן אחד לא צריך whipple3. **שניים כן.** גם קובץ אחד לא צריך git — הצורך מופיע ברגע
שעובד שני נוגע באותו מצב, ומשם הוא כבר לא נעלם.

מערכי multi-agent מתאמים היום דרך אחד משני ערוצים שבורים. או שהסוכנים מתכתבים
ביניהם בטקסט חופשי — שריפת טוקנים על תיאום, זיהום קונטקסט, ואפס יכולת ביקורת —
או שהכול עובר דרך אורקסטרטור, וזה בדיוק מה שקורה עם subagents של Claude Code:
כל subagent רץ מבודד ומחזיר להורה סיכום. עובדים מקבילים לא רואים זה את זה, אז הם
מכפילים עבודה, והקונטקסט של ההורה הופך לצוואר הבקבוק. יש דיווחים על פי ~7 טוקנים
בסשנים עתירי subagents לעומת ריצה בודדת — הרבה מזה תיאור-מחדש של מצב שכבר קיים
איפשהו.

whipple3 הוא ערוץ שלישי: גרף משותף, מוקלד (typed) ומבוסס-אירועים, שסוכנים קוראים
וכותבים אליו דרך מוטציות מובנות במקום צ'אט. זו ארכיטקטורת ה־blackboard הקלאסית
(שושלת Hearsay-II) עם שלוש תוספות מודרניות — סכמה מוקלדת, סוכני LLM, וליבה
event-sourced — ארוזה כשרת MCP, כך שהיא עובדת עם כל ראנטיים סוכנים שאתם כבר
מריצים.

הדיאגרמה המקובלת של סוכן — קלט, מודל, קריאות לכלים, סביבה מבודדת, זיכרון — יש בה
לולאה אחת, ו-whipple3 הוא לא קופסה בתוכה. ציירו סוכן שני והוא מופיע מיד:

```
      agent A                agent B                agent C
 ┌───────────────┐      ┌───────────────┐      ┌───────────────┐
 │  LLM → tools  │      │  LLM → tools  │      │  LLM → tools  │
 │   → sandbox   │      │   → sandbox   │      │   → sandbox   │
 └───────┬───────┘      └───────┬───────┘      └───────┬───────┘
         │        post / claim / read / release        │
         ▼                      ▼                      ▼
 ══════════════════════════════════════════════════════════════
   whipple3 — shared typed state
   checkAcl → apply → append         ← the one enforcement point
 ══════════════════════════════════════════════════════════════
                        │  append-only log = the truth
      ┌─────────────────┼──────────────────┐
      ▼                 ▼                  ▼
 blackboard_next     Studio          distill → your
 (next turn's        (live graph,     memory system
  context: sliced,    time travel)
  ACL-filtered)
      │
      └──→ replay → CI assertions
```

שימו לב מה מזין את התור הבא של הסוכן: **הכתיבות של הסוכנים האחרים**, מסוננות ל-slice
שהתפקיד שלו הצהיר עליו. לא ההיסטוריה שלו עצמו — זה זיכרון, והזיכרון הוא קופסה של
מישהו אחר. ה-sandbox מבודד סוכן↔מכונה; whipple3 מתווך סוכן↔סוכן.

## אם אתם מכירים Redux, אתם מכירים את הצורה

חנות אחת (store), והיא לא חלון הקונטקסט של אף סוכן. מוטציות הן actions מוקלדים.
`apply()‎` הוא reducer טהור — בלי I/O, בלי שעון, בלי אקראיות; זמן ומזהים מוזרקים
פנימה. לוג האירועים ה־append-only הוא מקור האמת והגרף הוא view — ולכן time-travel
debugging של סשן הסוכנים מתקבל בחינם: לא פיצ'ר שבנינו, תוצאה של הארכיטקטורה.
מריצים את הלוג מחדש ורואים את התיאום קורה שוב, דטרמיניסטית. ה־LLMs לא
דטרמיניסטיים; שכבת התיאום כן.

ומעל החנות הזאת:

- **Claims ו־leases.** עובד תופס (claim) צומת לפני שהוא נוגע בו. claim שני על צומת
  תפוס נדחה עם שם המחזיק האמיתי. claim נטוש פג ב־TTL והעבודה חוזרת לתור. אפס
  כפילות עבודה בין סוכנים מקבילים — מוכח ב־property tests על שזירות שרירותיות של
  claim/release/expiry.
- **זהות מהחיבור, לא מההצהרה.** אף payload לא נושא `agentId`; הזהות נקבעת כשהתהליך
  של הסוכן מתחבר. ACL שמפתחו שם שהסוכן מצהיר על עצמו — קישוט.
- **ACL דו־כיווני, וכל דחייה נרשמת.** רשימות labels לקריאה ולכתיבה פר סוכן. קריאות
  מסוננות תוך כדי חציית הגרף, כך שצומת אסור לא דולף דרך קצה של edge. כל דחייה היא
  אירוע `acl.denied` בלוג — אכיפה משאירה עקבות, אף פעם לא נעלמת בשקט.
- **קונטקסט תחום.** כל תפקיד מצהיר על slice מהגרף; הסוכן מקבל את ה־slice שלו, לא
  את הטרנסקריפט. סוכן אף פעם לא מרחיב לעצמו את הטווח — קריאה נושאת שורש, לא עומק.
  זה גם מה שהופך ציי מודלים זולים לסבירים: הסכמה עושה את החשיבה שמודל frontier
  היה עושה.

## הרמת מסך: איך ריצה נראית

בעברית של מוקד מוניות: גרסה 0.1 היא תחנה עם קשר — נהג שואל "מה יש בשבילי?"
(`blackboard_next`), עונים לו, הוא לוקח את הנסיעה. השלב הבא (Phase 2) הוא Gett —
המערכת דוחפת את הנסיעה לנהג המתאים. וההרנסים — Claude Code, Codex, Gemini CLI —
הם המכוניות: לעולם לא שלנו. אם צריך שורה אחת: **Gett לרתמות.** איפה המטאפורה
נשברת, וזה החלק המעניין: נסיעות הן בלתי תלויות זו בזו; צמתים בגרף נולדים
ומתקשרים זה לזה. תור בלבד לא מספיק — צריך תור **ועולם משותף מוקלד**. העולם הזה
הוא המוצר.

הדמו הארוז הראשון הוא `‎/whipple3:audit`, פלאגין ל־Claude Code. תהליך אחד של
`whipple3 serve` מחזיק את הלוח; חמישה subagents מתחברים כחמש זהויות אמיתיות מעל
Unix socket:

1. סורק מפרסם צומת `CodeFile` לכל קובץ שראוי לבדיקה — נתיבים ו־hashים בלבד, תוכן
   קבצים לא נכנס לגרף לעולם.
2. שלושה auditors רצים במקביל בלולאת `next → claim → audit → post finding →
   release`. אף אחד לא מחלק קבצים; ה־claims מחלקים. מסתכלים על הלוח ורואים auditor
   שני נהדף מקובץ תפוס — עם שם המחזיק.
3. fixer מפרסם צומתי `Fix` מוצעים ולא עורך כלום. אדם מאשר תיקונים ספציפיים; רק הם
   מוחלים, כל אחד מאחורי prompt ההרשאות של ה־host עצמו.
4. `whipple3 distill` מקפל את לוג הסשן לדוח markdown: ממצאים לפי label, טבלת
   פעילות פר סוכן, אימות replay. הגרף נמחק, ה־trace נשמר.

`[הקלטת סטודיו — 20 שניות: צמתים מופיעים כשהסורק מפרסם, שלושה צבעי claim נעים
על פני הקבצים, וסקרבר ה־time-travel גורר את הסשן אחורה]`

זה הסטודיו: גרף חי של מה שה־subagents שלכם עושים עכשיו, עם time-travel על לוג
הסשן. הוא קיים כי הלוג הוא מקור האמת — ה־UI הוא סך הכול fold מעליו.

## מה זה לא

בלי קריאות LLM בליבה — אף פעם; המודלים שייכים ל־host. לא אורקסטרטור ולא תחליף
פריימוורק: whipple3 עובד עם Claude Code היום ומדבר MCP, כך ש־Codex CLI, Gemini
CLI, Cursor ו־opencode הם אותו שרת עם host אחר — הרשימה הזאת תהפוך לטבלת תאימות
ככל שכל שורה תקבל ריצה אמיתית. לא שכבת הרצה/sandbox — לשכבה הזאת יש בעלים ואנחנו
רוכבים עליה. בלי שפת שאילתות לסוכנים: שישה כלים מוקלדים ותחומים, וזהו. וגם לא מערכת
זיכרון: זיכרון עונה על מה ש*סוכן אחד* ידע בשבוע שעבר, whipple3 עונה על מה ש*כולם* רואים
עכשיו וכמה מזה כל אחד רשאי לראות — ‏`whipple3 distill` מוסר את הסשן לשכבת הזיכרון שכבר
יש לכם.

## לנסות

```bash
npm install -g whipple3        # או: npx whipple3
whipple3 serve                 # טרמינל 1 — הלוח
claude --plugin-dir <repo>/examples/claude-code-plugin   # טרמינל 2
/whipple3:audit
```

דורש Node ≥ 22. ה־README בריפו מכיל את מסלול עשר הדקות ואת הרשימה הכנה של מה
שעדיין stub. רישיון MIT.

## סטטוס, בכנות

v0.1 הוא ה־vertical slice: dispatch במצב pull בלבד (ה־host עדיין מריץ את הסוכנים;
whipple3 הוא הקשר במוקד, עדיין לא הסדרן), סשנים אפמרליים בלבד, `claim.expired`
מוגדר אך עדיין לא נפלט, ו־ACL בדמו דורש קובץ `--policy` מפורש. הסקדולר במצב push,
אדפטרים ל־sandbox, OTel וכלי evals הם Phase 2 — מתוכננים מראש (טקסונומיית
האירועים שומרת להם מקום) אבל לא בנויים. אם שכבת התיאום לא מועילה בלעדיהם — עדיף
שנגלה עכשיו.

ריפו: `github.com/whipple3/whipple3` · הספק וה־ADRs בתוך הריפו — התכנון הוא החלק
הקריא.
